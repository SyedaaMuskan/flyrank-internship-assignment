# Week 2 – Frame It As Cases

## Overview

This repository contains my submission for **Week 2 – "Frame It As Cases"** in the **FlyRank AI Fluency Internship**.

The goal of this assignment is to transform technical projects into compelling case studies that communicate **the problem, engineering decisions, and outcomes**, rather than simply listing technologies or screenshots.

Instead of relying on generic AI-generated descriptions, this submission reflects my own development journey, technical challenges, and lessons learned while building real AI applications.

---

## Objectives

This assignment demonstrates my ability to:

* Present technical work as clear engineering case studies.
* Explain the reasoning behind technical decisions.
* Communicate in a consistent personal voice.
* Replace generic AI writing with authentic project storytelling.
* Build portfolio-ready content for recruiters and hiring managers.

## Case Study Structure

Each project follows the same framework:

1. **Problem** – What challenge existed?
2. **What I Built** – How I approached the problem, the technical decisions I made, and why.
3. **Outcome** – The results, impact, and lessons learned.

This structure keeps the focus on engineering thinking rather than simply listing tools and technologies.

---

## Voice Card

> **Clear • Practical • Curious • Honest • No Buzzwords**

This voice card guided every section of the document to ensure the writing remained authentic and reflected how I naturally communicate my work.

---

## Key Learning

One of the biggest takeaways from this assignment is that a portfolio is not just a collection of projects—it's a collection of stories that demonstrate problem-solving, decision-making, and continuous learning.

Rather than saying *what* I built, I learned how to explain *why* I built it, *how* I made technical decisions, and *what* I learned throughout the process.
