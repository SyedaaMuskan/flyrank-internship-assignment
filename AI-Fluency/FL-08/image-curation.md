# AI Fluency — Week 03: Image Curation

## Purpose

The goal of this exercise was to decide which images genuinely strengthen my portfolio rather than simply using AI-generated images because they look attractive.

My main rule was:

> **Real work should be shown with real evidence. AI-generated visuals should only support the presentation of the work.**

The visual direction follows my identity kit:

- Minimal
- Modern
- Premium
- Calm
- Thoughtful
- Editorial

The image choices should support the work without competing with it.

---

# 1. Image Needs for My Portfolio

My portfolio needs images in three main categories.

## A. Real Project Evidence

These should be real captures of work I actually created.

### Backend Engineering

For my backend projects, I will use real screenshots such as:

- FastAPI Swagger documentation
- API endpoints and responses
- PostgreSQL database results
- Docker Compose running the application
- Relevant code or architecture views when they help explain a decision

### AI Fluency

For my AI Fluency work, I will use real screenshots of:

- Prompt iterations
- AI outputs
- Portfolio/case-study work
- Identity kit
- Other actual deliverables from the internship

These images are evidence of the work, so I will not replace them with AI-generated representations.

---

# 2. Real Captures vs AI-Generated Images

## Real captures

I chose real captures when the image needs to prove that I actually completed something.

Examples:

| Portfolio Need | Decision | Reason |
|---|---|---|
| FastAPI project | Real screenshot | Shows the actual API |
| PostgreSQL project | Real screenshot | Proves database integration |
| Docker project | Real screenshot | Shows the actual development environment |
| Prompt iteration | Real screenshot | Shows actual AI work |
| Portfolio work | Real screenshot | Shows the actual result |

The screenshots should be clean, cropped, and legible rather than showing an entire desktop with unrelated windows.

---

## AI-generated visuals

AI-generated images are appropriate only for connective or decorative elements.

Possible uses include:

- Hero background texture
- Very subtle abstract shapes
- Small supporting visual elements
- Decorative backgrounds that do not pretend to represent real work

These visuals should follow one consistent visual direction.

---

# 3. AI Image Style

The AI-generated visuals should match the identity kit.

### Style

- Minimal
- Editorial
- Calm
- Abstract
- Subtle
- Premium
- Lots of negative space
- Warm off-white background
- Muted blue accents
- Charcoal details
- No photorealistic fake screenshots
- No fake product interfaces
- No unnecessary 3D objects

### Palette

- `#F7F6F2`
- `#171717`
- `#2D2D2D`
- `#6B7C93`

The generated visuals should feel like part of the same visual system rather than a collection of unrelated AI images.

---

# 4. AI Image Selection

I would generate multiple options rather than automatically accepting the first result.

For every generated image, I would ask:

1. Does it match my visual identity?
2. Does it help the visitor understand the portfolio?
3. Does it distract from the actual work?
4. Does it look consistent with the other images?
5. Would I still use it if I had a real screenshot available?

An attractive image is not automatically a useful image.

---

# 5. Rejected AI Image

### Rejected option

I rejected AI-generated visuals that were too decorative, visually busy, or disconnected from the actual work.

### Why I rejected them

Some generated options looked impressive on their own but would have competed with the project screenshots.

The purpose of my portfolio is to communicate the quality of my work, not the quality of the image generator.

I therefore rejected visuals that had:

- Too much visual detail
- Strong gradients
- Excessive 3D effects
- Generic "AI" imagery
- Unnecessary futuristic objects
- A style that did not match the identity kit

The key judgment was:

> **Looking good is not enough. The image has to serve a purpose.**

---

# 6. Where I Chose Real Work Over AI

I deliberately chose real captures for project evidence.

For example, for my backend engineering projects, a real screenshot of my FastAPI API, PostgreSQL database, or Docker environment is stronger than an AI-generated image representing what those things might look like.

A generated image can look polished, but it cannot prove that I actually built the project.

Therefore:

**Evidence → real capture**

**Decoration → AI can be considered**

---

# 7. Image Curation Rules

My final portfolio will follow these rules:

### Rule 1 — Evidence must be real

Screenshots and visuals that prove my work will come from the actual project.

### Rule 2 — AI should not fake the work

I will not use AI-generated screenshots, fake dashboards, fake code, or fake project results as evidence.

### Rule 3 — One visual language

AI-generated supporting images must follow the same calm, minimal, editorial style.

### Rule 4 — Less is better

I would rather use fewer strong images than fill the portfolio with decorative images.

### Rule 5 — The work remains the focus

If an image attracts more attention than the project itself, I will question whether it belongs.

---

# 8. Final Image Set

The final portfolio image set will consist primarily of:

- Real screenshots of my backend projects
- Real screenshots of my AI Fluency work
- Real photographs where I am the subject
- A small number of carefully selected AI-generated supporting visuals
- My portfolio logo and favicon

The images will be cropped consistently and presented using the visual identity defined in my Identity Kit.

---

# What I Learned

The biggest lesson from this exercise was that **generation is not the same as judgment**.

AI can create many images quickly, but that does not make all of them useful.

I learned to evaluate an image based on:

- Relevance
- Evidence
- Consistency
- Clarity
- Restraint
- Purpose

The strongest portfolio image is not necessarily the most impressive image.

It is the image that makes the work easier to understand and trust.

> **AI can generate the options. I make the decision.**
